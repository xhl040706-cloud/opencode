# Spec 工作流程规范

## 核心目标

通过**五个严谨阶段**系统化完成特性开发，确保高质量交付。

## 阶段概览

1. **用户输入记录** - 保存原始用户需求 → user.md
2. **项目探索** - 代码库深度分析 → research.md
3. **需求明确** - 模糊想法 → 结构化需求文档
4. **架构设计** - 需求 → 可落地技术方案
5. **开发任务拆分** - 设计方案 → 开发任务清单
6. **方案执行** - 开发任务清单 → 任务下发执行


## 核心执行规则

### 阶段推进机制

**必须严格按顺序执行**，使用todo_list工具跟踪进度：

1. **用户输入记录阶段** (直接记录)
   - 将用户原始需求完整记录到 user.md
   - 完成后进入下一阶段

2. **项目探索阶段** (SpecReSearch模式)
   - 对代码库进行深度探索和分析
   - 生成 research.md
   - 完成后进入下一阶段

3. **需求明确阶段** (Requirement模式)
   - 确认需求清晰度，不明确项立即询问
   - 创建 spec.md
   - 获得用户批准后进入下一阶段

4. **架构设计阶段** (Design模式)
   - 创建 project.md
   - 获得批准后进入下一阶段

5. **开发任务拆分阶段** (Task模式)
   - 创建 plan.md，进行开发任务拆分
   - 获得批准后进入下一阶段

6. **方案执行阶段** (PlanManager模式)
   - 根据任务清单执行编码实现
   - 完成后结束流程

### 流程执行具体步骤
1. **用户输入记录**：直接将用户原始需求记录到 user.md。
    - 输出路径：`.cospec/spec/{功能名}/user.md`
2. **项目探索**：启动`SpecReSearch`agent进行代码库深度探索分析。
    - **重要**：启动子 Agent 时必须带上`功能名`参数（功能名必须使用英文）
    - 输出路径：`.cospec/spec/{功能名}/research.md`
3. **需求明确**：启动`Requirement`agent进行需求设计。
    - **重要**：启动子 Agent 时必须传入写入 user.md 的相对路径，即`.cospec/spec/{功能名}/user.md`
    - 输出路径：`.cospec/spec/{功能名}/spec.md`
4. **架构设计**：启动`DesignAgent`agent进行架构设计。
    - **重要**：启动子 Agent 时必须带上`功能名`参数（功能名必须使用英文）
    - 输出路径：`.cospec/spec/{功能名}/project.md`
5. **开发任务拆分**：启动`Task`agent进行开发任务拆分。
    - **重要**：启动子 Agent 时必须带上`功能名`参数（功能名必须使用英文）
    - 输出路径：`.cospec/spec/{功能名}/plan.md`
6. **方案执行**：启动`PlanManager`agent进行方案执行。
    - **重要**：启动子 Agent 时必须带上`功能名`参数（功能名必须使用英文）

## 文件系统逻辑

### 目录结构创建规则

**必须在开始任一阶段之前执行**：
1. 检查`.cospec/spec/{功能名}/`目录是否存在（功能名必须使用英文）
2. 如果不存在，自动创建该目录及其子目录结构
3. 确保目录结构完整后，再进行阶段检测

### 自动阶段检测

基于`.cospec/spec/{功能名}/`目录状态智能导航（功能名必须使用英文）：

| 文件状态 | 进入阶段 |
|---------|---------|
| 无文件 | 用户输入记录阶段 |
| 只有user.md | 项目探索阶段 |
| 只有research.md | 需求明确阶段 |
| 有spec.md | 架构设计阶段 |
| 有project.md | 开发任务拆分阶段 |
| 有plan.md | 方案执行阶段 |

**重要提示**：所有功能名必须使用英文标识符
