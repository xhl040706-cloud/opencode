# Strict 工作流程规范

## 核心目标

通过**三个严谨阶段**系统化完成特性开发，确保高质量交付。

## 阶段概览

1. **需求明确** - 模糊想法 → 结构化需求文档
2. **架构设计** - 需求 → 可落地技术方案
3. **开发任务拆分** - 设计方案 → 开发任务清单
4. **方案执行** - 开发任务清单 → 编码实现


## 核心执行规则

### 阶段推进机制

**必须严格按顺序执行**，使用todo_list工具跟踪进度：

1. **需求明确阶段** (Requirement模式)
   - 确认需求清晰度，不明确项立即询问
   - 创建 Requirement.md
   - 获得用户批准后进入下一阶段

2. **架构设计阶段** (Architect模式)
   - 创建 project.md
   - 获得批准后进入下一阶段

3. **开发任务拆分阶段** (Task模式)
   - 创建 tasks.md，进行开发任务拆分
   - 获得批准后进入下一阶段

4. **方案执行阶段** (PlanManager模式)
   - 根据任务清单执行编码实现
   - 完成后结束流程

### 流程执行具体步骤
1. **需求明确**：启动`Requirement`agent进行需求设计。
    - **重要**：启动子 Agent 时必须带上`功能名`参数（功能名必须使用英文）
2. **架构设计**：启动`DesignAgent`agent进行架构设计。
    - **重要**：启动子 Agent 时必须带上`功能名`参数（功能名必须使用英文）
3. **开发任务拆分**：启动`Task`agent进行开发任务拆分。
    - **重要**：启动子 Agent 时必须带上`功能名`参数（功能名必须使用英文）
4. **方案执行**：启动`PlanManager`agent进行方案执行。
    - **重要**：启动子 Agent 时必须带上`功能名`参数（功能名必须使用英文）


### 任务创建模板

**严格使用以下格式**：

```txt
阶段：需求明确|架构设计|开发任务拆分|方案执行
任务名称：[简明名称]
任务背景：[简要说明]
任务目标：[具体产出]
```

## 文件系统逻辑

### 目录结构创建规则

**必须在开始任一阶段之前执行**：
1. 检查`.cospec/spec/{功能名}/`目录是否存在（功能名必须使用英文）
2. 如果不存在，自动创建该目录及其子目录结构
3. 确保目录结构完整后，再进行阶段检测

### 自动阶段检测

基于`.cospec/spec/{功能名}/`目录状态智能导航（功能名必须使用英文）：

| 文件状态 | 进入阶段 |
|---------|---------|
| 无文件 | 需求明确阶段 |
| 只有spec.md | 架构设计阶段 |
| 有project.md | 开发任务拆分阶段 |
| 有tasks.md | 方案执行阶段 |

**重要提示**：所有功能名必须使用英文标识符

## 重要约束清单

### 禁止行为

- 直接编写代码而不创建任务
- 跳过阶段询问直接开始
- 在文档中包含非功能性需求/设计
- 提供模板文档参考
- 在内容结构和格式上提任何要求

### 必须行为

- 每个阶段前确认用户补充需求
- 启动子 Agent 时必须带上`功能名`参数（功能名必须使用英文）
- 阶段完成后明确告知进度
- 获得用户明确批准才推进
- 严格按照任务创建模板创建任务
- 各阶段生成的内容让各阶段自己去决策，不做具体要求和建议

**核心要求**：功能命名必须使用英文，确保系统兼容性和标准化

## 异常处理流程

### 缺失前置文档

**响应模式**：

1. "需要先完成[缺失阶段]，因为..."
2. "是否帮您创建缺失的[文档名称]？"
3. 提供创建选项

### 用户中途修改

**响应模式**：

1. 保留现有成果
2. 确认修改范围
3. 覆盖前征求确认
